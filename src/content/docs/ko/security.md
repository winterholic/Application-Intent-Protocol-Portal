## 표현은 권한이 아니다 {#expression-not-authority}

AIP는 프론트엔드가 필요한 데이터와 동작을 표현하게 한다. 그 편의 때문에 보안 경계가 프론트엔드로 옮겨 가지는 않는다. 호출자가 무엇을 보내든 허용 범위와 실행 방식은 서버가 결정한다. `Decided`

## 서버가 항상 시행하는 것 {#required-checks}

다음 검사는 필수이며 항상 서버가 시행한다. `Decided`

- 인증과 인가
- 타입과 입력 제약
- 데이터 무결성
- 권한 범위
- 트랜잭션 안전성
- 실행 비용과 자원 제한

[AI를 위한 설계](/ko/docs/concepts/ai-first/#verification)에서 설명한 선택적 개발 검사는 별개다. 그것을 쓰지 않아도 필수 검사는 생략되지 않는다.

## 확장도 같은 규칙을 따른다 {#extensions}

JS/TS나 Python 확장도 서버의 보안 정책과 계약을 따라야 한다. 권한, 비용 제한, 트랜잭션을 피해 가는 길이 아니다. 운영 환경에서 확장을 실행하는 격리 수준은 `Open`이다. [확장](/ko/docs/concepts/extensions/)을 참고한다.

## 자연어는 보안 입력이 아니다 {#natural-language}

자연어로 쓴 설명은 실행 권한이나 보안 판단에 쓰지 않는다. AIP는 무엇을 실행할지 정하려고 요청마다 자연어를 해석하지 않는다. `Decided`

## 검증 중인 방향 {#direction}

| 주제 | 방향 |
|---|---|
| 새 필드 | 안전한 기본값으로, 명시적으로 열기 전까지 호출자에게 숨긴다. `Direction` |
| 읽기의 숨은 부작용 | 명시적으로 선언한 경우에만 허용한다. `Direction` |
| 데이터 손실이나 권한 확대가 있는 배포 | 기본적으로 명시적 승인과 영향 확인을 거친다. `Direction` |
| 권한 오류의 상세도 | 비공개 리소스나 권한 구조를 드러내지 않는 범위에서 개발자에게 유용하게. `Direction` |
| 오픈소스와 서버 접근 | 프레임워크 소스가 공개됐다고 운영 중인 서버가 공개되는 것은 아니다. 실제 서버는 인증, 권한, 리소스 정책으로 접근을 제한한다. `Direction` |
