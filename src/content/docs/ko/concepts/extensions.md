## 표준이 먼저, 확장은 공식 경로로 {#paved-road}

AIP는 표준 기능과 하나의 명확한 표준 표현으로 최대한 많은 것을 다루려 한다. 그래도 실제 애플리케이션에는 어떤 표준도 미리 알 수 없는 로직이 있다. 이를 위해 AIP는 JavaScript/TypeScript와 Python 공식 확장을 제공한다. `Decided`

확장은 임시 우회 수단이 아니고, 쓸 때마다 특별 승인을 받아야 하는 예외도 아니다. AIP의 정식 구성 요소다. 다만 확장으로 서버 규칙을 피해 갈 수는 없다.

## 확장이 지키는 것 {#controls}

확장도 다른 모든 것과 같은 통제 아래에서 실행된다.

- 타입과 데이터 접근 계약
- 권한
- 실행 비용 제한
- 트랜잭션 경계

확장은 서버의 보안 정책을 우회해서는 안 된다. `Decided`

## 누가 쓰는가 {#authors}

애플리케이션 개발자와 AI 에이전트가 JS/TS나 Python으로 확장을 쓴다. `Decided` 서드파티 확장 패키지 생태계를 처음에 어디까지 지원할지는 `Open`이다.

## 아직 검증 중인 것 {#open}

- 확장 인터페이스(ABI)와 Rust 엔진·JS/TS·Python 사이의 실행 경계는 가정하지 않고 실제 비용과 확장성을 측정해 설계한다.

## 1.0에서 제공하는 것 {#in-1-0}

1.0은 OS 샌드박스에서 워커를 실행한다. 플랫폼별 조건은 [확장과 워커](/ko/docs/workers/)에 있다. Node.js와 Python 워커는 정의에 선언한다. 쓰기 확장은 호출자의 정책 아래에서 읽고, 전이를 부르고, 행을 만들 수 있으며 업무 코드로 호출을 거절할 수 있다. durable job과 플랫폼별 격리는 [확장과 워커](/ko/docs/workers/)를 참고한다.
