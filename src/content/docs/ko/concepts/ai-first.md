## AI-first의 뜻 {#meaning}

AIP는 AI가 코드의 많은 부분을 작성하고 유지보수하는 시대를 전제로 설계한다. 이것은 `Decided`다. 하지만 다음을 뜻하지 **않는다**.

- 사람 개발자가 쓰기 어려운 프레임워크
- 사람의 가독성을 포기한 문법
- AI만 쓸 수 있는 프로그래밍 언어
- 기존 프레임워크에 더한 AI 코드 생성 기능
- 지금의 복잡한 구조를 AI가 더 빨리 쓰게 돕는 것에 그치는 것

목표는 사람과 AI 모두가 이해하고 검증할 수 있으면서, 존재할 필요가 없는 구현 작업을 없애는 구조다.

## 하나의 명확한 방법 {#one-clear-way}

같은 것을 만드는 동등한 방법이 열 가지면 AI 에이전트는 매번 하나를 골라야 하고, 고른 것이 달라지면 일관성이 깨진다. AIP는 가능한 곳에서 표준 기능과 하나의 명확한 표준 표현을 제공한다. 모든 자유를 없애는 것이 아니라 근거 없는 구현 다양성을 없애려는 것이다. 표준이 맞지 않는 곳은 [확장](/ko/docs/concepts/extensions/)이 맡는다. `Decided`

문법은 다음과 같은 질문으로 평가한다.

- 무엇이 어느 선언에 속하는지 분명한가?
- 같은 개념을 항상 같은 방식으로 표현하는가?
- 타입과 제약을 쉽게 파악할 수 있는가?
- 암묵적인 동작이 적은가?
- AI가 쓸 수 있는 표준 기능을 쉽게 찾을 수 있는가?
- 잘못된 표현을 정적으로 찾기 쉬운가?
- 불필요하게 장황하지 않으면서 사람이 이해할 수 있는가?

창시자는 선언형 문법을 선호한다. 구체 문법과, 그것을 독립 파일에 쓸지 JS/TS·Python 안에 쓸지는 `Open`이다.

## 정해진 자리를 갖는 설명 {#metadata}

일반 주석은 어느 선언을 설명하는지 모호할 수 있다. AIP는 자연어 설명에 특정 선언에 붙는 정해진 자리를 준다. `Decided`

- 작성은 선택이고 길이를 강제하지 않는다.
- 기본적으로 의미를 자동 검증하지 않는다.
- 실행 권한이나 보안의 근거로 쓰지 않는다.
- 무엇을 실행할지 정하려고 요청마다 자연어를 해석하지 않는다.

AIP는 자연어 프레임워크가 아니다. 동작, 권한, 검증은 정형화된 형태로 정의한다.

## 두 종류의 검사 {#verification}

AIP는 검사를 두 계층으로 나눈다. `Decided`

| 계층 | 예 | 위치 |
|---|---|---|
| 필수 실행 안전성 | 인증과 인가, 타입과 입력 제약, 데이터 무결성, 권한 범위, 트랜잭션 안전성, 비용과 자원 제한 | 항상 서버가 시행 |
| 선택적 개발 검사 | 정적 분석, 구조적 일관성, 중복 구현 탐지, AI가 쓴 코드 점검, 권고 | 개발자가 원할 때 사용 |

선택 계층을 쓰지 않았다고 필수 계층이 생략되지는 않는다. 선택 계층이 어떤 검사를 제공할지, 자동 수정이 가능할지는 아직 설계 중이다.
