이 원칙들은 창시자가 직접 밝힌 내용에서 왔다. 기존 코드, 설계 문서, 기여자 간 합의보다 우선한다. 일곱 가지 모두 `Decided`다.

## AIP가 존재하는 이유 {#purpose}

> 서버는 안전한 실행 환경을 제공한다. 프론트엔드가 필요한 데이터와 동작을 표현하면, 백엔드에 매번 API를 추가하지 않고도 애플리케이션이 동작해야 한다.

> 요청의 자유와 실행 권한을 분리한다.

## 일곱 가지 원칙 {#principles}

### 1. 애플리케이션별 백엔드 작업 최소화 {#principle-backend}

AIP 서버를 설치하고 설정하면 공통 기능을 수행할 준비가 되어 있어야 한다. 프론트엔드가 필요한 것을 표현함으로써 많은 기능을 별도의 서버 API 구현 없이 쓸 수 있어야 한다. 백엔드를 없애려는 것은 아니다. 애플리케이션마다 반복되는 구현과 유지보수를 최소화하려는 것이다.

### 2. 새로운 Application Intent Protocol {#principle-protocol}

AIP는 REST endpoint를 생성하는 프레임워크가 아니다. 프론트엔드가 필요한 데이터와 동작을 표현하는 통신 모델이다. 무언가를 표현할 수 있다는 것과 실행해도 된다는 것은 다르다. 허용 범위와 실행 방식은 서버가 결정한다.

### 3. Rust 엔진과 JavaScript/TypeScript·Python {#principle-ecosystem}

핵심 실행 엔진은 Rust를 쓴다. 개발자는 JavaScript/TypeScript와 Python 생태계에서 자연스럽게 작업하며, 특히 JS/TS 경험을 중요하게 본다. Rust 엔진이 개발자에게 불필요한 복잡성을 강요해서는 안 된다.

### 4. AI를 위한 정형화와 근거 없는 선택 줄이기 {#principle-structure}

AI가 기능을 구현할 때 동등한 패턴 여럿 중 하나를 임의로 골라야 하는 상황을 줄인다. AIP는 표준 기능과 정형화된 문법을 제공하고, 가능한 곳에서는 하나의 명확한 표준 표현을 제공한다. 자유를 모두 없애려는 것은 아니다. 근거 없이 갈라지는 구현을 줄이려는 것이다.

### 5. 자연어 메타데이터의 구조화 {#principle-metadata}

AIP는 설명을 특정 선언에 붙일 수 있는 정해진 자리를 제공해, 설명이 무엇에 속하는지 항상 분명하게 한다. 작성은 선택이고, 의미를 자동 검증하지 않으며, 권한이나 보안의 근거로 쓰지 않는다.

### 6. SPR: Specification, Presentation, Runtime {#principle-spr}

Specification은 서버 측 모델, 허용 범위, 권한, 정책, 업무 규칙, 확장 계약을 정의한다. Presentation은 프론트엔드가 필요한 데이터와 동작을 표현하는 방식이다. Runtime은 요청을 검증하고 정책에 따라 안전하게 실행한다. [SPR](/ko/docs/concepts/spr/)을 참고한다.

### 7. JavaScript/TypeScript·Python 공식 확장 {#principle-extensions}

표준 기능으로 처리할 수 없는 복잡하거나 특수한 로직은 JS/TS나 Python으로 작성한다. 임시 우회 수단이 아니라 공식 확장 구조이며, 확장도 서버의 보안 정책과 계약을 따른다. [확장](/ko/docs/concepts/extensions/)을 참고한다.

## 모든 설계가 답해야 하는 질문 {#design-questions}

1. 기존의 어떤 반복 구현을 없애는가?
2. 화면이나 기능을 추가할 때 서버 코드를 얼마나 덜 고치게 되는가?
3. 프론트엔드와 백엔드의 계약 중복이 줄어드는가?
4. AI가 스스로 골라야 하는 구현 방식이 줄어드는가?
5. 사람 개발자가 이해하고 검증할 수 있는가?
6. 보안과 데이터 무결성이 유지되는가?
7. 복잡성을 다른 계층으로 옮기기만 한 것은 아닌가?

이 질문에 답하지 못하는 추상화는 다시 검토한다.

## 자주 오해하는 것 {#misreadings}

- "호출자가 표현한다"는 무제한 요청을 뜻하지 않는다. 호출자는 서버가 허용한 계약 안에서 요청한다.
- AI-first는 사람이 쓰기 어렵다는 뜻이 아니다. AI 전용 언어도, 사람의 가독성을 포기하는 것도 아니다.
- Rust는 엔진의 구현 언어다. 개발자가 정의를 무엇으로 쓰는지와는 별개다.
- 문법, 중간 표현, 컴파일러는 목적이 아니라 수단이다.
