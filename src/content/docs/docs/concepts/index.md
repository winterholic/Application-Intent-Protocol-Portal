이 페이지는 AIP Core의 원칙 정본에서 확정된 부분만 옮긴다. 원칙을 구현하는 구체 문법과 API는 아직 정해지지 않았다.

## AIP를 만드는 이유

> 서버는 안전한 실행 환경을 제공하고, 프론트엔드에서 필요한 데이터와 동작을 표현하면 백엔드에 매번 API를 추가하지 않고도 처리할 수 있어야 한다.

> 요청의 자유와 실행 권한을 분리한다.

AIP는 서버를 없애려는 것이 아니다. 인증·인가·비즈니스 규칙·데이터 무결성의 책임을 프론트엔드로 넘기려는 것도 아니다.

## 원칙

1. 애플리케이션별 백엔드 반복 구현과 유지보수를 최소화한다.
2. 호출자는 필요한 데이터와 동작을 표현하고, 서버가 권한과 실행을 최종 결정한다.
3. 핵심 엔진은 Rust로 만들고, JS/TS·Python 생태계와 자연스럽게 연결한다.
4. AI를 위해 표현을 정형화하고 근거 없는 구현 선택을 줄인다. 사람이 이해하고 검증할 수 있어야 한다.
5. 선언에 붙는 자연어 설명은 선택 사항이다. 실행과 보안의 근거가 아니다.
6. 서버는 계약과 정책을 정의하고, 프론트는 표현하고, Runtime은 안전하게 실행한다.
7. 표준 밖의 동작은 JS/TS·Python 공식 확장으로 처리하되 계약·권한·비용·트랜잭션 통제를 유지한다.

## 자주 혼동되는 것

- 호출자가 표현한다는 것은 무제한 요청을 뜻하지 않는다. 서버가 허용한 계약 안에서 요청한다.
- Rust는 핵심 엔진의 구현 언어다. 개발자가 정의를 무엇으로 쓰는지와는 별개다.

## 아직 정해지지 않은 것

독립 `.aip` 파일의 필요성, 최종 정의 문법, 초기 TS/Python 지원 범위, 첫 프론트 통합 대상은 미정이다.
