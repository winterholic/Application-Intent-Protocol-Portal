## 表現は権限ではない {#expression-not-authority}

AIP はフロントエンドが必要なデータと操作を表現できるようにします。その利便性によってセキュリティ境界がフロントエンドに移ることはありません。呼び出し側が何を送っても、許可範囲と実行方法はサーバーが決めます。`Decided`

## サーバーが常に実施するもの {#required-checks}

次のチェックは必須で、常にサーバーが実施します。`Decided`

- 認証と認可
- 型と入力の制約
- データ整合性
- 権限の範囲
- トランザクションの安全性
- 実行コストとリソースの制限

[AI のための設計](/ja/docs/concepts/ai-first/#verification)で説明した任意の開発チェックは別物です。それを使わなくても必須チェックは省かれません。

## 拡張も同じルールに従う {#extensions}

JS/TS や Python の拡張も、サーバーのセキュリティポリシーと契約に従わなければなりません。権限、コスト制限、トランザクションを迂回する道ではありません。本番環境で拡張を実行する分離レベルは `Open` です。[拡張](/ja/docs/concepts/extensions/)を参照してください。

## 自然言語はセキュリティの入力ではない {#natural-language}

自然言語で書かれた説明は、実行の権限やセキュリティの判断に使いません。AIP は何を実行するかを決めるために、リクエストごとに自然言語を解釈しません。`Decided`

## 検証中の方向 {#direction}

| テーマ | 方向 |
|---|---|
| 新しいフィールド | 安全な既定値として、明示的に公開するまで呼び出し側から隠す。`Direction` |
| 読み取りの隠れた副作用 | 明示的に宣言した場合のみ許可する。`Direction` |
| データ損失や権限拡大を伴うデプロイ | 既定で明示的な承認と影響の確認を行う。`Direction` |
| 権限エラーの詳細度 | 非公開のリソースや権限構造を明かさない範囲で、開発者に役立つように。`Direction` |
| オープンソースとサーバーへのアクセス | フレームワークのソースが公開されていても、稼働中のサーバーが公開されるわけではない。実際のサーバーは認証、権限、リソースポリシーでアクセスを制限する。`Direction` |
