SPR は責任を理解するためのモデルとして `Decided` です。SPR という名前で具体的なパッケージ構成や内部実装を固定することはしません。

## Specification {#specification}

サーバー側で、データモデル、許可範囲、権限、ポリシー、業務ルール、拡張の契約を定義します。アプリケーション開発者が何が起きてよいかを述べる場所です。

## Presentation {#presentation}

フロントエンドが公式フロントエンドライブラリを通じて、必要なデータと操作を AIP の構造化された形で表現します。画面が何を求めるかを述べる場所です。

## Runtime {#runtime}

ランタイムは各リクエストを検証し、ポリシーに従って安全に実行します。リクエストを実行するかどうか、どう実行するかをサーバーが決める場所です。

## 三つの関係 {#flow}

| 段階 | 責任 | 担い手 |
|---|---|---|
| 画面が必要なものを表現する | Presentation | フロントエンド |
| リクエストを契約とポリシーに照らして確認する | Specification を使う Runtime | サーバー |
| 許可されたリクエストを実行する | Runtime | サーバー |
| 標準機能の外のロジックを実行する | Specification の契約下の拡張 | サーバー |

呼び出し側が見られる契約とサーバー内部のポリシーは別物です。契約のどの部分を公開するかは `Open` です。
