## まず標準、足りなければ公式の拡張 {#paved-road}

AIP は標準機能と一つの明確な標準表現で、できるだけ多くを扱おうとします。それでも実際のアプリケーションには、どの標準も予測できないロジックがあります。そのために AIP は JavaScript/TypeScript と Python の公式拡張を提供します。`Decided`

拡張は一時的な回避策でも、毎回特別な承認が必要な例外でもありません。AIP の正式な構成要素です。ただし、サーバーのルールを迂回する道は与えません。

## 拡張が守るもの {#controls}

拡張も他のすべてと同じ統制のもとで動きます。

- 型とデータアクセスの契約
- 権限
- 実行コストの制限
- トランザクション境界

拡張はサーバーのセキュリティポリシーを迂回してはいけません。`Decided`

## 誰が書くか {#authors}

アプリケーション開発者と AI エージェントが JS/TS または Python で拡張を書きます。`Decided` サードパーティの拡張パッケージのエコシステムを最初にどこまでサポートするかは `Open` です。

## まだ検証中のもの {#open}

- 本番環境で拡張を実行する分離技術。実験では、拡張を別プロセスで動かすだけではデータベースへの直接接続を防げませんでした。分離レベルは `Open` です。
- 拡張インターフェース (ABI) と、Rust エンジンと JS/TS・Python の間の実行境界は、仮定ではなく実測したコストと拡張性から設計します。
