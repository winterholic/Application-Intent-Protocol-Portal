## 四つの構成要素 {#parts}

| 構成要素 | 役割 | ステータス |
|---|---|---|
| AIP サーバーフレームワーク | インストールと設定の後、標準機能を内蔵して自前のポートで動く | `Decided` |
| AIP フロントエンドライブラリ | フロントエンドがデータと操作を表現する公式の方法 | `Decided` |
| Application Intent Protocol | 両者の間の通信モデル | `Decided`。wire 形式の詳細は `Open` |
| 共通実行エンジン | リクエストを実行する Rust エンジンと、契約・ポリシーの仕組み | `Decided` |

サーバーとフロントエンドライブラリは互いを置き換えるものではありません。AIP は両方を提供します。Node や Python のパッケージからサーバーを自動起動する方式は、開発の利便機能として検討中です。`Open`

## Spring Boot と同じ始まり方、ただし最初から機能がある {#spring-boot}

Spring Boot プロジェクトをインストールして設定すると、アプリケーションサーバーがポートで起動します。機能を実装するまでは、ほとんど何もしません。

AIP も同じ始まり方を目指します。インストールして設定すれば、サーバーが自前のポートで動きます。違いは、AIP サーバーがすでに豊富な標準機能を備えていることです。データベース接続、データモデル、権限ポリシーは引き続き設定します。画面ごとに controller、service、API を実装することはしません。`Decided`

## リクエストの経路 {#request-path}

1. フロントエンドライブラリが、画面が表現したものを送る。
2. ランタイムが呼び出し側を認証し、リクエストを契約とポリシーに照らして確認する。
3. エンジンが許可されたリクエストを計画・実行し、コストとリソースの制限を守る。
4. 標準機能の外のロジックは、同じ契約のもとで拡張として実行される。
5. 結果がフロントエンドライブラリに返る。

これは責任の所在を説明したものです。プロトコルと wire の詳細は `Open` です。

## 現在存在するもの {#implementation-today}

AIP Core リポジトリには動作するプロトタイプがあります。リリースではなく、その動作が仕様でもありません。2026-10-06 時点で、リポジトリには次のものがあります。

- PostgreSQL を対象にサーバーを動かす Rust エンジンと `aip service` コマンド
- 運用アクセストークン (RS256 JWT) の検証と、サーバー側での actor への対応付け
- 計画を立ててトランザクションで適用するデータベースマイグレーション
- ローカルにインストールする TypeScript SDK パッケージと、アプリケーションの契約から生成した型
- サーバーの統制のもとで動く Node.js・Python の拡張

macOS とローカルの PostgreSQL で検証しました。外部 ID プロバイダー、TLS プロキシでのデプロイ、他の OS は試していません。プロトタイプが使う定義の構文は最終的な AIP の構文ではありません。[現状](/ja/docs/status/)を参照してください。
