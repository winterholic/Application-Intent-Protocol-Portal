これらの原則は創設者自身の言葉に基づいています。既存のコード、設計文書、コントリビューター間の合意より優先します。七つすべてが `Decided` です。

## AIP が存在する理由 {#purpose}

> サーバーは安全な実行環境を提供する。フロントエンドが必要なデータと操作を表現すれば、毎回バックエンドに API を追加しなくてもアプリケーションが動くべきだ。

> 要求の自由と実行の権限を分離する。

## 七つの原則 {#principles}

### 1. アプリケーション固有のバックエンド作業を最小化する {#principle-backend}

AIP サーバーをインストールして設定すれば、共通機能を実行する準備ができているべきです。フロントエンドが必要なものを表現することで、多くの機能を個別のサーバー API 実装なしで使えるべきです。目標はバックエンドをなくすことではなく、アプリケーションごとの繰り返し実装と保守を最小化することです。

### 2. 新しい Application Intent Protocol {#principle-protocol}

AIP は REST endpoint を生成するフレームワークではありません。フロントエンドが必要なデータと操作を表現する通信モデルです。何かを表現できることと、それを実行してよいことは別です。許可範囲と実行方法はサーバーが決めます。

### 3. Rust エンジンと JavaScript/TypeScript・Python {#principle-ecosystem}

中核の実行エンジンには Rust を使います。開発者は JavaScript/TypeScript と Python のエコシステムで自然に作業し、特に JS/TS の体験を重視します。Rust エンジンが開発者に不要な複雑さを強いてはいけません。

### 4. AI のための構造化と、根拠のない選択の削減 {#principle-structure}

AI が機能を実装するとき、同等なパターンの中から一つを任意に選ばなければならない状況を減らします。AIP は標準機能と構造化された構文を提供し、可能な限り一つの明確な標準表現を提供します。すべての自由をなくすのではなく、根拠なく生じる実装の多様性を最小化することが目的です。

### 5. 自然言語メタデータの構造化 {#principle-metadata}

AIP は説明を特定の宣言に結び付ける決まった場所を提供し、説明が何に属するかを常に明確にします。記述は任意で、意味は自動検証されず、権限やセキュリティの根拠には使いません。

### 6. SPR: Specification, Presentation, Runtime {#principle-spr}

Specification はサーバー側のモデル、許可範囲、権限、ポリシー、業務ルール、拡張の契約を定義します。Presentation はフロントエンドが必要なデータと操作を表現する方法です。Runtime はリクエストを検証し、ポリシーに従って安全に実行します。[SPR](/ja/docs/concepts/spr/) を参照してください。

### 7. JavaScript/TypeScript・Python の公式拡張 {#principle-extensions}

標準機能で扱えない複雑または特殊なロジックは JS/TS または Python で書きます。一時的な回避策ではなく公式の拡張構造であり、拡張もサーバーのセキュリティポリシーと契約に従います。[拡張](/ja/docs/concepts/extensions/)を参照してください。

## すべての設計が答えるべき問い {#design-questions}

1. 既存のどの繰り返し実装をなくすか?
2. 画面や機能を追加するとき、サーバーのコード変更はどれだけ減るか?
3. フロントエンドとバックエンドの契約の重複は減るか?
4. AI が自分で選ばなければならない実装方法は減るか?
5. 人間の開発者が理解し、検証できるか?
6. セキュリティとデータ整合性は保たれるか?
7. 複雑さを別の層に移しただけではないか?

これらに答えられない抽象化は見直します。

## よくある誤解 {#misreadings}

- 「呼び出し側が表現する」は無制限のリクエストを意味しません。呼び出し側はサーバーが許可した契約の範囲で要求します。
- AI-first は人にとって使いにくいという意味ではありません。AI 専用の言語でも、人の可読性を捨てることでもありません。
- Rust はエンジンの実装言語です。開発者が定義を何で書くかとは別の話です。
- 構文、中間表現、コンパイラは目的ではなく手段です。
