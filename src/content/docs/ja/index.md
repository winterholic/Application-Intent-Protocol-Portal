AIP (Application Intent Protocol) の出発点はシンプルです。画面に新しいデータや操作が必要になると、チームは今もそれを新しい endpoint、controller、service、DTO、検証、認可チェック、API ドキュメントに置き換え、そのすべてをフロントエンドとバックエンドの両方で保守しています。

AI はそのコードをより速く書けます。しかし重複がなくなるわけではありません。

AIP は別の道を取ります。フロントエンドは必要なデータと操作を構造化された形で表現します。豊富な標準機能を内蔵するよう設計中の AIP サーバーは、開発者が定義した契約とポリシーに照らしてリクエストを確認し、実行します。アプリケーション固有のバックエンドコードは、本当にそのアプリケーション固有のものだけに減ります。

> [!IMPORTANT]
> AIP は設計と検証が進行中です。公開リリースはまだなく、定義の構文も確定していません。このドキュメントは AIP Core プロジェクトが決定した内容だけを記し、それ以外は `Direction` または `Open` と明示します。[現状](/ja/docs/status/)を参照してください。

## AIP とは {#what-aip-is}

- インストールして設定すると自前のポートで動き、標準機能がすでに組み込まれた**バックエンドサーバーフレームワーク**
- アプリケーションが必要なデータと操作を表現する**フロントエンドライブラリ**
- 両者の間の **Application Intent Protocol**
- Rust で書かれた**共通実行エンジン**と、サーバーの統制を保つ契約・ポリシーの仕組み

AIP が対象とする問題は [Why AIP](/ja/docs/why-aip/) に、すべての設計判断が守るべきルールは[原則](/ja/docs/concepts/)にあります。

## AIP ではないもの {#what-aip-is-not}

- バックエンドをなくしません。認証、認可、データアクセス制御、業務上の不変条件、データ整合性、トランザクション、リソース制限はサーバーに残ります。
- REST endpoint の生成器ではありません。GraphQL と CQRS からアイデアを得ていますが、その複製でもありません。
- 既存のフレームワークに AI 機能を加えたものではなく、自然言語のプロンプトをアプリケーションロジックとして実行するものでもありません。
- 新しい汎用プログラミング言語ではありません。開発者は JavaScript/TypeScript と Python のエコシステムを使い続けます。

## このドキュメントの読み方 {#how-these-docs-work}

すべてのページは冒頭と Markdown 版にステータスを表示します。

| ステータス | 意味 |
|---|---|
| `sourced` | AIP Core プロジェクトが決定した内容だけを、出典リンクとともに記した |
| `stub` | 場所だけがある。内容は AIP Core の決定待ち |

ページ内の項目は AIP Core プロジェクトと同じ語彙で示します。この語彙は翻訳しません。

| 表示 | 意味 |
|---|---|
| `Decided` | 創設者が直接述べた、または明示的に決定した |
| `Direction` | 創設者の意図に沿った方向。詳細は検証が必要 |
| `Open` | まだ決まっていない |

## AI コーディングエージェントのために {#for-ai-agents}

HTML ページと以下のテキスト版は同じソースファイルから生成されるため、互いにずれることはありません。

| パス | 内容 |
|---|---|
| `/llms.txt` | 全ページの一覧と Markdown のパス |
| `/llms-full.txt` | 全ページの本文 |
| `/docs/<page>.md` | ページの Markdown 版。ページ URL の末尾の `/` を `.md` に置き換える |

```sh
curl https://aip-portal.vercel.app/llms.txt
curl https://aip-portal.vercel.app/docs/concepts.md
```

`#what-aip-is` のような節 id は、文言や言語が変わっても維持します。`Open` と示されたものは未決定です。AIP を説明するときも AIP のコードを生成するときも、推測で埋めないでください。
