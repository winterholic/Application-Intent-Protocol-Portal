AIP 正处于设计与验证阶段。本页反映上述日期时 AIP Core 的文档内容，并随其变化而更新。

> [!IMPORTANT]
> `Open` 表示 AIP 尚未决定答案。无论是人还是 AI 编码智能体，在解释 AIP 或为其编写代码时，都不要用猜测填补这些条目。

## Decided {#decided}

| 主题 | 决定 |
|---|---|
| 目的 | 在不取消后端的前提下，最小化应用特有的后端实现以及前后端的重复维护 |
| 调用模型 | 调用方表达所需的数据和操作，服务器决定并执行 |
| 读取 | 调用方组合的读取在服务器策略下执行 |
| 简单写入 | 尽可能以标准形式支持，而不是每次修改都写一个服务器 command |
| 产品形态 | 在自己端口上运行的 AIP 服务器框架，加上官方前端库 |
| 引擎与生态 | Rust 引擎；JavaScript/TypeScript 与 Python 生态，特别重视 JS/TS |
| 扩展 | 处于服务器契约与控制之下的 JS/TS 和 Python 官方扩展 |
| 语法方向 | AIP 特有的结构化定义表达方式，偏好声明式风格 |
| 自然语言元数据 | 可选，附着于声明，绝不作为执行或安全的依据 |
| 检查 | 区分服务器端必需的安全检查与可选的开发检查 |
| 开源 | 以开源方式开发，欢迎外部贡献 |

## Direction {#direction}

| 主题 | 方向 |
|---|---|
| 生产环境中未注册的读取形态 | 在安全、性能和成本验证的前提下，于策略范围内允许 |
| 批量失败 | 原子操作全部成功或全部失败；部分成功的批量模式在评估中 |
| 部署环境 | 优先普通服务器和容器；无服务器稍后分析 |
| 页面同步 | 默认基于重新获取；实时同步作为可选功能候选 |
| 前端库范围 | 优先数据访问、请求构建、契约处理和状态同步 |

## Open {#open}

| 主题 | 问题 |
|---|---|
| 定义格式 | 是否需要独立的 `.aip` 文件，以及具体语法 |
| 写入组合 | 调用方组合写入的自由程度，以及事务边界 |
| 语言对等 | 首个版本中 TS 与 Python 的功能是否相同 |
| 前端集成 | 先做框架无关的核心，还是先做 React 等首个官方集成 |
| 扩展生态 | 第三方扩展包的初始范围 |
| 扩展隔离 | 生产环境运行扩展的隔离级别 |
| 数据库 | 支持的数据库和 capability 模型。目前在 PostgreSQL 上验证 |
| 兼容性 | 字段重命名后，旧字段继续可用多久 |
| 首个版本的调用方 | 首个版本中谁可以直接编写请求 |
| 许可证 | 具体的开源许可证 |

## 原型验证 {#prototype}

AIP Core 仓库中有一个把已验证部件组装成单个服务器的原型，截至 2026-10-06：

- 运维 JWT 验证以及服务器端 actor 映射
- 先规划、再以事务方式应用的数据库迁移
- 本地安装的 TypeScript SDK，以及从契约生成的类型
- 在服务器控制下运行的 Node.js 和 Python 扩展
- 在 macOS 上的真实 PostgreSQL 中运行

这些是原型的测试结果，不是正式发布的保证。外部身份提供方、TLS 代理部署和其他操作系统尚未测试，原型的定义语法也不是最终版本。详情：[product/VERIFICATION.md](https://github.com/winterholic/Application-Intent-Protocol/blob/main/product/VERIFICATION.md)。
